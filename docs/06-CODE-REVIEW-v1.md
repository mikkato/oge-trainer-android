## Что проверено по паролям

- PBKDF2-HMAC-SHA256, 210 000 итераций, соль 16 байт, ключ 256 бит; соль и хеш — base64.
- Сравнение — `MessageDigest.isEqual` (постоянное время), не `String.equals`.
- Хеширование и проверка выполняются в `Dispatchers.IO`, главный поток не блокируется.
- Пароль не логируется, в `Profile` уходит только хеш (с солью), исходный пароль нигде не хранится.
- Минимальная длина — 6 символов; текст отказа конкретный.

## Сброс базы пользователей (выполнено)

Схема поднята до версии 2, в миграции `1 → 2`:

```sql
ALTER TABLE profiles ADD COLUMN builtin INTEGER NOT NULL DEFAULT 0;
DELETE FROM attempts; DELETE FROM topic_mastery;
DELETE FROM program_subjects; DELETE FROM programs; DELETE FROM profiles;
```

После миграции встроенный администратор создаётся заново репозиторием. На устройстве это означает: старые профили (в том числе демо-«Иван») удалены, история попыток и освоение очищены, в списке входа остаётся один профиль — **Администратор (`admin`)**, помеченный «встроенный».

Отдельная кнопка «Сбросить профили» в админке вызывает тот же `resetUsers()` — сброс можно повторить без переустановки.

## Принятый риск (по решению заказчика)

Пароль встроенного администратора хранится в исходниках (`ProfilesRepository.BUILTIN_PASSWORD`), потому что учётка «закреплена физически». Последствия:

- любой, кто получил APK или репозиторий, знает пароль к локальным данным;
- сменить его можно только полным сбросом профилей (`resetUsers`) — это осознанное ограничение, чтобы «закреплённая» учётка не могла быть перехвачена сменой пароля;
- данные ребёнка (ответы и попытки) в этом контуре не защищены от владельца разблокированного телефона — это соответствует модели «семейное устройство», но не корпоративной.

Если потребуется иначе: вынести пароль в первый запуск (мастер), а `builtin` оставить только как запрет удаления — это правка одного метода `ensureBuiltinAdmin`.
