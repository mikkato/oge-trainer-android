# ТЗ: Android-приложение «Тренировочная система» (ОГЭ-тренажёр) — v1

Основание: реверс `00-REVERSE-oge-trainer-web-v1.md` (13.11.2026). Предмет ТЗ — перенос полного пользовательского функционала веб-приложения `train.mytolm.ru` на нативный Android-клиент.

## 1. Термины

| Термин | Значение |
|---|---|
| Сервер | FastAPI-приложение `oge-api` + SQLite за `https://train.mytolm.ru` |
| Клиент | Android-приложение (Kotlin + Compose), устанавливается как APK |
| Тема | Узел кодификатора (2 уровня), 103 темы на 5 предметов |
| Доверенная задача | Задача, помеченная родителем как проверенная; выдаётся ученику первой |
| Освоение | Число 0..1 по теме, EMA от результатов попыток |
| Режим ответа | `short` (тест), `extended` (развёрнутый), `izlozhenie`, `sochinenie` (только русский) |

## 2. Цели

| ID | Цель |
|---|---|
| G-1 | Ученик проходит полный цикл «предмет → тема → теория → задача → проверка → прогресс» на телефоне без браузера |
| G-2 | Родитель с телефона видит отчёт по детям и управляет пулом доверенных задач |
| G-3 | Приложение работает при плохой сети: конспекты и задачи читаются из кэша, ответы уходят в очередь и не теряются |
| G-4 | Ни один элемент веб-функционала не теряется при переносе (кроме редактора контента, которого в вебе нет) |
| G-5 | Стоимость эксплуатации не растёт: сервер и LLM остаются прежними, новых платных сервисов нет |

## 3. Не входит в объём

- Генерация заданий на устройстве (LLM остаётся на сервере).
- Регистрация и восстановление пароля самообслуживанием (учётки создаёт администратор).
- Офлайн-проверка ответов LLM (проверка только на сервере; офлайн — очередь).
- Публикация в Google Play / RuStore в первой версии (распространение — APK).
- iOS, планшетная оптимизация сверх адаптивной вёрстки.
- Учительские роли, классы, расписание, экспорт в школы.
- Правка существующих дефектов сервера, не влияющих на перенос (кроме перечисленных в разделе 9 как обязательные).

## 4. Пользователи и роли

| Роль | Что видит | Ограничения сервера |
|---|---|---|
| `student` | свои предметы, темы, теорию, задачи, освоение | нет доступа к отчётам, проверке задач, админке (403) |
| `parent` | отчёт по всем ученикам, очередь проверки задач, пометка `trusted` | нет доступа к админке, задач не решает |
| `admin` | админка: пользователи, программы, пароли, сброс тренинга, AI-провайдер | нет доступа к отчёту (`/reports/overview` требует `parent`) |

Роль приходит в `GET /api/me`; клиент обязан строить навигацию от роли, а не от сохранённого флага.

## 5. Архитектура

```
┌──────────────────────── Android (Kotlin 2.2 / Compose) ────────────────────────┐
│ UI (Compose, Material3, токены из web)                                         │
│  ├ auth   ├ subjects/topics   ├ theory(Markdown+KaTeX)   ├ practice            │
│  └ report ├ review            └ admin                                          │
│                                                                                │
│ domain: use cases (GenerateTask, SubmitAttempt, RefreshProgress…)              │
│ data:   ApiClient (Ktor 3.6.1) ── Room 2.8.5 (кэш и outbox) ── DataStore 1.3   │
│         TokenStore (EncryptedSharedPreferences / Keystore)                     │
└────────────────────────────────┬───────────────────────────────────────────────┘
                                 │ HTTPS, JWT Bearer
                    ┌────────────▼─────────────┐
                    │ nginx → FastAPI (oge-api)│──► DeepSeek API
                    │ SQLite /data/app.db      │
                    └──────────────────────────┘
```

Решения и обоснование:

| Решение | Обоснование | Отвергнутая альтернатива |
|---|---|---|
| Нативный клиент, сервер сохраняется | Весь контент и проверка — LLM на сервере (замер: 1,6 с генерация, 1,1 с проверка); переносить нечего, кроме клиента | WebView-обёртка: нет офлайна, нет нативного ввода, не «стек Андроид» |
| Генерация только онлайн, чтение из кэша | Ключ провайдера нельзя отдавать на устройство (R-09); качество проверки развёрнутых ответов на устройстве не воспроизводится | Локальная модель: не тянет критерии ИК/СК и физику 2–3 балла |
| Markdown+LaTeX рендерит WebView с офлайн-KaTeX (ассеты из текущей web-сборки) | Полная визуальная идентичность формул с вебом, нулевой риск расхождения | Markwon 4.6.2 + jlatexmath-android 0.2.0 — как резерв, если WebView не пройдёт гейт G1 |
| Room как кэш + outbox попыток | Требование G-3; сервер не хранит «черновики» | Только память: потеря ответа при сворачивании |

## 9. Безопасность

- Пароль не хранится на устройстве; токен — Keystore, `FLAG_SECURE` на экране ввода пароля.
- `android:allowBackup="false"` для данных приложения (иначе токен и кэш попадают в облачный бэкап).
- Сертификат-пиннинг не внедряется (Let's Encrypt ротирует цепочку), но включён `network_security_config` с запретом cleartext.
- Обязательные серверные работы до бета-сборки: FR-S3, FR-S4, FR-S6, FR-S8 (R-01, R-02, R-03 в отчёте реверса).
- Логи приложения — только идентификаторы; текст задания и ответа не логируются.

| Плотность | вертикальные отступы списков 6–8 dp, между блоками 12 dp, поля ввода 48 dp |

Требования к интерфейсу: плотная компоновка без декоративных заливок, элементы одной строки выровнены по общей оси, размеры шрифтов и элементов задаются в процентах от базовых значений темы, служебные подписи (номер сборки, версия) на рабочих экранах не показываются.

## 11. Критерии приёмки

| ID | Критерий и методика |
|---|---|
| AC-1 | Полный цикл ученика на реальном устройстве: вход → предмет → тема → теория с формулами → задача → ответ → разбор → возврат на карточки; пройдено на 5 предметах × 4 режимах (20 прогонов), все экраны без ошибок |
| AC-2 | Рендеринг формул: 20 реальных условий из базы (дроби, корни, степени, векторы, системы) отображаются идентично вебу — сверка скриншотов 1:1 на 3 темах |
| AC-3 | Отчёт родителя: цифры на экране совпадают с `/api/reports/overview` (сверка полей: освоение, попытки, верных, слабые места, рекомендации) на всех учениках |
| AC-4 | Доверенный пул: задача, помеченная `trusted`, выдаётся ученику первой (проверка до и после переключения) |
| AC-5 | Офлайн: в авиарежиме открываются кэшированные темы и конспекты; отправленный ответ попадает в outbox, после включения сети автоматически проверяется, дублей в `attempts` нет (проверка по `id`) |
| AC-6 | Негативные сценарии: 401 → экран входа; 403 (student на `/api/tasks/review`) → «нет доступа»; 502 теории → кнопка «Повторить»; обрыв сети на середине проверки → ответ не потерян |
| AC-7 | Админка: создание пользователя с программой, смена пароля, сброс тренинга — по одному разу каждая операция на тестовой учётке, состояние подтверждено чтением списка |
| AC-8 | Производительность: замеры NFR-1, NFR-2 на AVD API 36 и на физическом устройстве (методика: Macrobenchmark для старта, ручной замер прокрутки 3 экранов) |
| AC-9 | Безопасность: токен отсутствует в `adb backup`, в logcat и в `shared_prefs/*.xml` открытым текстом (проверка `adb shell run-as` + `strings`) |
| AC-10 | Сборка воспроизводима: `./gradlew :app:assembleRelease` на чистом окружении даёт подписанный APK; инструкция по установке приложена |

## 12. Открытые вопросы

| ID | Вопрос | Предложение исполнителя |
|---|---|---|
| OQ-1 | На каком устройстве и версии Android будет эксплуатироваться приложение? | Минимум — Android 8 (API 26); тест на вашем телефоне; если телефон на Android 12+ — поднять `minSdk` до 31, сэкономив на совместимости |
| OQ-2 | Админка нужна в мобильном виде или достаточно веба? | Перенести всё, кроме формы AI-провайдера: правка ключа с телефона — редкое и опасное действие |

| OQ-5 | Входят ли серверные доработки FR-S1…S8 в этот же контракт? | Входят, кроме FR-S2/FR-S5 как отдельная итерация: без S3/S4/S6/S8 бета-сборку выпускать нельзя |
| OQ-6 | Кто ведёт контент (пометка `trusted`) в новой схеме? | Родитель из мобильной очереди проверки; практика покажет, нужен ли режим «доверять автоматически после N успешных решений» |
