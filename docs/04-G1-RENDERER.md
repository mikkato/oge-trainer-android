# Гейт G1: рендер markdown и формул — протокол

Дата: 13.11.2026. Устройство: AVD `LSDF_Pixel_36` (Android 16, API 36, 1080×2400, 420 dpi), сборка `app-release.apk` 0.1.0.

## Решение

Принят **вариант A: WebView + офлайн-ассеты KaTeX 0.19.1 + marked 18.2.0**, HTML-обёртка в `assets/render/template.html`, высота контента возвращается в Compose через JS-мост.

Вариант B (`io.noties.markwon:core` 4.6.2 + `ru.noties:jlatexmath-android` 0.2.0) не реализовывался: последний релиз jlatexmath-android — 0.2.0, порт не обновлялся годами, а совпадение с web-версией не гарантируется. Вариант A дал визуально идентичный результат на реальных данных, поэтому B остаётся резервом, если A упрётся в производительность на длинных конспектах.

## Что проверено (на реальном банке)

| Проверка | Результат |
|---|---|
| Конспект темы «Треугольники» (`math.geom.1`) | Все формулы отрисованы: `S = ½ah`, формула Герона `S = √(p(p−a)(p−b)(p−c))`, `c² = a² + b²`, `sin/cos/tan` с дробями |
| Конспект «Линейные и квадратные уравнения» | `ax + b = 0`, `ax² + bx + c = 0`, `a ≠ 0`, дискриминант — инлайн и выноски |

## Ловушки, которые пришлось снять (все воспроизводимы)

1. **`file://`-страница не грузит относительные скрипты** с API 30: `allowFileAccessFromFileURLs` по умолчанию выключен, KaTeX и marked не подхватывались, `renderMarkdown` не существовал. Решение: `loadDataWithBaseURL("file:///android_asset/render/", …)` + явное включение file-доступа.
2. **`evaluateJavascript` из `update` приходит раньше `window.load`** — вызов теряется, экран пустой. Решение: текст хранится в теге WebView, рендер повторяется в `onPageFinished`, страница ставит вызов в очередь до готовности.
3. **JS-мост не приводит `float` к `Int`** и падает с `Java exception was raised during method invocation`. Решение: `Math.round(h)` в JS и сигнатура `onHeight(px: Double)` в Kotlin.
4. **Колбэк моста приходит не в главном потоке** — запись в состояние Compose оттуда падает. Решение: `Handler(Looper.getMainLooper()).post { … }`.
5. **WebView с высотой 1 px не раскладывает страницу** (`scrollHeight = 0`), измерить нечего. Решение: до первого измерения окно 600 dp.
6. **CSS-пиксели ≠ dp после деления на плотность.** JS отдаёт CSS px, которые при `viewport=device-width` уже равны dp: `.toDp()` сжимал карточку в одну строку. Решение: `contentHeightPx.dp`.
7. **Высота меняется после подстановки шрифтов KaTeX** — без `ResizeObserver` и `document.fonts.ready` карточка оставалась обрезанной на первой строке.

Все семь пунктов записаны в коде `MarkdownView.kt` и `template.html` комментариями, чтобы не изобретать их заново.

## Что этот гейт не покрывает

- Производительность длинных конспектов при быстрой прокрутке (замеров fps не делали; конспект на 2198 px листался без рывков на глаз).
- Ширина колонки на телефоне: на экране темы конспект живёт в правой колонке ≈180 dp и читается плохо. Это дефект компоновки, а не рендера; исправление — в этапе 1 (полноэкранная теория вместо двух колонок на телефоне).
- Печать/зум формул, горизонтальная прокрутка выносок в узкой колонке.
