## 5. Доменная логика, которую надо перенести без изменений

| Правило | Реализация | Класс |
|---|---|---|
| Освоение темы | EMA: `mastery = clamp(0.7·mastery + 0.3·score)` при каждой попытке | [Ф] |
| «Тема освоена» | `mastery ≥ 0.8` | [Ф] |
| «Слабая тема» | `attempts_count > 0 и mastery < 0.5`, топ-8 по возрастанию | [Ф] |
| Доверенные задачи | ученику сначала выдаётся `trusted` задача по теме/типу, которую он ещё не решал; родителю и `force_fresh` — всегда свежая генерация | [Ф] |
| Баллы по типу | short 1–2 (`max_points` от модели), extended 2 (физика 2–3 по оценке чекера), изложение 6, сочинение 7 | [Ф] |
| Быстрый путь проверки | нормализация (нижний регистр, без пробелов, `,`→`.`) и точное совпадение — только для short | [Ф] |
| Критерии проверки | изложение ИК1–ИК3 (0–2 каждый), сочинение СК1–СК4 (0–1/0–3/0–2/0–1), <70 слов → 0 баллов | [Ф] |
| Кросс-дисциплинарные рекомендации | словарь `CROSS_LINKS` из 12 пар «код темы → целевая тема + причина» захардкожен в `reports.py` | [Ф] |
| Иллюстрации теории | 69 курированных SVG в `backend/app/illustrations/`, отдаются inline-строками по коду темы | [Ф] |
| Кодификаторы | 103 темы по 5 предметам, дерево из 2 уровней, задаётся в `seed.py` | [Ф] |

## 6. LLM-слой

Системы промптов: генерация и проверка для 5 предметов × режимы (short/extended), отдельные системы для изложения и сочинения, отдельная для теории. Модель вызывается с `response_format=json_object`, `temperature=0.4`, до 3 повторов, `_parse_json` чинит обрезанный JSON и умеет вытаскивать поля регуляркой.

Замеры (прямой вызов API DeepSeek из контейнера `oge-api`, 13.11.2026):

| Операция | Время | Токены (prompt+completion) |
|---|---|---|
| Генерация задания (math, short) | 1,6 с | 84 + 96 = 180 |
| Проверка ответа | 1,1 с | 110 + 32 = 142 |

Вывод: задержки приемлемы для мобильного сценария при наличии сети; кэширование конспектов и пул доверенных задач снижают число вызовов. **[И]** Стоимость на одну задачу определяется тарифом DeepSeek (в отчёте не приводится — тариф не сверялся).

## 8. Ревью: дефекты и риски

Порядок — по влиянию на перенос и на эксплуатацию. P1 — блокирует/опасно, P2 — мешает, P3 — гигиена.

| ID | Приоритет | Находка | Следствие | Класс |
|---|---|---|---|---|
| R-01 | P1 | `JWT_SECRET` — 20 байт; PyJWT на каждом выпуске токена пишет `InsecureKeyLengthWarning` | Слабый секрет подписи; при утечке `.env` подделка токенов любого пользователя, включая admin | [Ф] |
| R-02 | P1 | Пароли по умолчанию в `seed.py` открытым текстом: `admin`/`!Ytcnthjdf221120`, `parent`/`parent2026`, `ivan`/`ivan2027`, `vasilisa`/`vasilisa6` | Восстановление базы = повторное создание этих учёток; пароль администратора лежит в исходниках | [Ф] |
| R-03 | P1 | Нет ограничения частоты на `/api/auth/login` и на `/api/tasks/generate` | Перебор пароля; выжигание баланса DeepSeek любым авторизованным пользователем | [Ф] |
| R-04 | P1 | Конфиг деплоя на диске расходится с работающим (порты 80/443 против loopback 8081/8444); git отсутствует | `docker compose up` ломает вход через host-nginx; откат на «предыдущую версию» невозможен | [Ф] |
| R-05 | P2 | Нет refresh-токена и отзыва; TTL 24 ч, logout только стирает токен на клиенте | В мобильном приложении — вход заново каждые сутки или бессрочное хранение токена | [Ф] |
| R-06 | P2 | Нет API истории попыток (только `POST /api/attempts`) | Ученик не видит свои прошлые задания и ошибки — на Android это заметная дыра | [Ф] |
| R-07 | P2 | `POST /api/attempts` не идемпотентен | Повторная отправка при обрыве сети создаёт дубль и дважды двигает mastery | [Ф] |
| R-08 | P2 | Проверка ответа синхронная в HTTP-запросе (LLM) | Таймаут клиента при медленном ответе; на мобильной сети — до 30–90 с | [Ф] |
| R-09 | P2 | `api_key` провайдера хранится в SQLite открытым текстом | Утечка файла базы = утечка ключа | [Ф] |
| R-10 | P2 | Логика «освоено ≥0.8», EMA и агрегаты продублированы в `topics.py` и `reports.py` | Расхождение цифр между экраном предмета и отчётом после правки в одном месте | [Ф] |

| R-14 | P2 | Резервного копирования `app.db` нет (файл один, без реплики) | Потеря прогресса обоих детей при повреждении файла | [Ф] |
| R-15 | P3 | `Task.type` нормализуется UPDATE-ом при каждом старте | Лишняя запись, скрытая переклассификация старых задач | [Ф] |

## 9. Границы проверки (что не проверено)

- Не проверялись сценарии с реальной записью: генерация, отправка ответа, пометка `trusted`, админские мутации (всё это меняло бы базу владельца). Формы запросов и ответов взяты из кода и подтверждены типами, но не прогоном.
- Не проверялось поведение DeepSeek на длинных режимах (изложение 3 000 токенов, сочинение 3 000) — замерена только генерация short и проверка.
- Не проверялся реальный мобильный браузер и поведение KaTeX на Android WebView.
- Не проверялись сертификаты/продление для `train.mytolm.ru` (снята только дата `notAfter` = 06.02.2027 через s_client).
- Не проверялись права файлов и бэкапы `.env`, содержимое `ai_config.api_key` (длина 0 — используется ключ из env).
