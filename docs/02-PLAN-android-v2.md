# План: Android-приложение «Тренировочная система» — v2 (автономное)

Версия 2 учитывает решение заказчика: **сервер после реверса демонтируется**. Приложение перестаёт быть клиентом и становится самодостаточным: банк контента внутри APK, прогресс на устройстве, LLM — только если настроен провайдер.

## 1. Главный вывод

Перемена архитектуры не увеличила объём, а перераспределила его: исчезла серверная волна (было 19 ч), но появились локальные вход, освоение, отчёты и импорт банка (те же ~20 ч). Итог: **MVP 112 ч → 129 ч с буфером (≈4 недели)**, полная версия **162 ч → 186 ч (≈5,8 недели)** при 32 ч/нед.

Критично по времени только одно — **забрать контент с сервера до демонтажа**. Это уже сделано (`03-CONTENT-EXPORT-v1.md`): кодификатор, конспекты по всем темам, банк задач, иллюстрации, фоны, история попыток. Дальше спешки нет.

## 2. Принципы

1. Первый гейт — рендеринг формул (KaTeX) в первые три дня: без него вся вёрстка задач и теории переделывается.
2. Автономность проверяется с первого дня: каждый экран обязан открываться в авиарежиме, сеть — необязательный источник.
3. Прогресс не пересчитывается нигде, кроме одного места (`RecomputeMastery`), иначе экраны начнут расходиться, как это было в вебе (R-10 реверса).
4. Провайдер — сменный адаптер, а не «DeepSeek-клиент»: два протестированных endpoint (облачный и локальный) в приёмке.
5. Банк и база — разные вещи: банк в `assets` версионируется, база в Room мигрирует.

## 5. Порядок работ для ИИ-исполнителя

1. Прочитать `AGENTS.md` и `03-CONTENT-EXPORT-v1.md`; проверить, что `assets/content-v1` на месте и счётчики совпадают с `meta.json`.
2. Создать проект, `assembleDebug`, запуск на AVD — приложение открывается в авиарежиме.
3. Перенести токены темы; экран-заглушка совпадает с вебом по цветам, радиусам и плотности.
4. Реализовать Room и импорт банка; проверить: `tasks` = счётчик из `meta.json`, повторный запуск не дублирует.
5. Профили и вход; проверить: неверный пароль, блокировка после 5 попыток, авиарежим.
6. Спайк рендера (P1-1), решение фиксируется в `AGENTS.md` до вёрстки задач.
7. Экран предметов и дерево тем; проверить: освоение 0 у нового профиля, галочка при ≥0,8 в тестовых данных.
8. Экран теории; проверить: открывается без сети, SVG на месте, формулы не ломают прокрутку.
9. Практика: выдача задачи и локальная проверка; проверить эквивалентность нормализации с вебом (5 кейсов: пробелы, запятая, регистр, дроби).
10. Освоение и история; проверить: EMA 0,7/0,3 на 3 попытках совпадает с ручным расчётом.
11. Провайдер: настройка, «Проверить подключение» на облачном endpoint.
12. Генерация и проверка через провайдер; проверить на локальном endpoint (llama.cpp/Ollama) — тот же код, другой URL.
13. Отчёт и очередь проверки; сверить агрегаты с эталонным скриптом.
14. Админка: 4 операции, каждая подтверждена чтением списка.
15. Экспорт/импорт: перенос файла на второе устройство/профиль, отсутствие дублей.
16. Релиз: keystore, GitHub Actions по тегу, установка APK по ссылке, прогон AC-1…AC-10.

## 7. Риски

| ID | Риск | Вероятность / влияние | Мера |
|---|---|---|---|
| TR-1 | KaTeX в WebView не даёт нужной вёрстки | Средняя / высокое (+1 нед) | Гейт G1 в первые 3 дня; резерв Markwon + jlatexmath; третий вариант — предрендер HTML в банке |
| TR-2 | Качество предзагруженного банка (модель могла ошибиться в ответе) | Высокая / среднее | Короткие ответы проверяются точным совпадением, ошибка видна сразу; очередь проверки родителем; пометка `origin=bank`; в v1.1 — перепроверка через провайдер |
| TR-3 | Ключ провайдера на устройстве | Средняя / среднее | Шифрование Keystore, маска, отсутствие логов; предупреждение при включении |
| TR-4 | Нет синхронизации: два телефона — два прогресса | Высокая / низкое | Экспорт/импорт файла (FR-806); решение OQ-3 |
| TR-5 | «Любой endpoint» — разное поведение JSON-режима | Средняя / среднее | Парсер как в вебе (починка обрезанного JSON, извлечение полей регуляркой), два протестированных endpoint, fallback без `response_format` |
| TR-6 | Ошибка в миграциях Room ломает прогресс при обновлении APK | Средняя / высокое | Тесты миграций, экспорт перед обновлением, `fallbackToDestructiveMigration` только в debug |
| TR-7 | Расползание объёма (расписание, статистика по дням, достижения) | Средняя / высокое | Раздел «не входит» в ТЗ; новые идеи — в бэклог v1.1 |
| TR-8 | Публичный GitHub с ключами или банком, содержащим персональные данные | Низкая / высокое | Приватный репозиторий, ключи только в Secrets, история попыток детей в репозиторий не кладётся (только банк) |

## 8. Что требуется от заказчика

1. **GitHub**: аккаунт/организация, имя репозитория, публичный или приватный (OQ-1). Для приватного ссылка из Releases требует авторизации — либо публичный репозиторий, либо раздача файла отдельно.
2. **Ключ DeepSeek с сервера** — забрать из `.env` контейнера `oge-api` до демонтажа, если планируется использовать тот же тариф; в приложении ключ вводится в админке.
3. **Решение по OQ-2** (провайдер по умолчанию) и **OQ-3** (обмен прогрессом между устройствами).
4. **Пароль keystore** (получен) — при первой сборке создаётся `keystore.jks`, пароль уходит в GitHub Secrets и в вашу сохранённую копию; в репозиторий не коммитится.
5. **Точка демонтажа сервера**: подтвердить, что после выгрузки (`~/content-export`, счётчики в `meta.json`) его можно гасить; до этого — не выключать, я могу добрать конспекты или задачи, если найдутся пробелы.
