## 2. Новая модель обучения (с нуля)

Единица программы — **тема ФРП** из `assets/school/thematic_plan.json` (frp-2026):

```
код темы:  <subj><grade>.<раздел>.<номер>   напр. geo7.2.3
свойства:  название, раздел, часы, kind (topic/practical/lab/control/project)
```

- Профиль ученика = класс → доступны темы своего класса **и всех нижних**
  (принципиальное отличие: нижние классы разблокируются для повторения, mastery затухает).
- `kind` задаёт поведение: `topic` — задачи из пула; `practical/lab` — чек-лист/каркас
  работы + вопросы по ходy; `control` — не генерируется, помечает конец раздела;
  `project` — карточка-каркас.
- **ОГЭ — отдельный экзаменационный трек**, не предмет и не класс:
  `subject=oge`, темы = существующие ОГЭ-коды банка (`math.*`, `rus.*`) + предметные
  темы 9 класса как «вход»; внутри — форматированные тренировки по номерам заданий
  и пробники (диагностика = mock, уже есть) с таймером и отдельным mastery `oge.<predmet>`.
  Трек доступен с 8 класса, приоритет тем — по актуальным спецификациям (405 доверенных
  задач ОГЭ остаются ядром, LLM-дополнение только после приёмки).
- Старый `curriculum.json` остаётся только перечнем предметов программы профиля;
  древо тем строится из плана.

## 3. Антизаучивание (главный вопрос пользователя)

Задача — чтобы порядок решения и сами формулировки не запоминались. Слоями:

1. **Пул + исключение решённого** (уже есть в `StudyRepository`): из 5–15 задач на тему
   ученику всегда приходит непросенная, порядок перемешан seed'ом профиля.
2. **Параметрические шаблоны** для того, что вообще выводимо кодом (математика, русский
   орфография/пунктуация, физика формулы): бесконечное число вариантов одной идеи —
   модель тут не нужна вообще. Расширять `LocalTemplates`/`RussianTemplates` под ФРП-темы.
3. **Регенерация по исчерпанию пула**: последние задачи темы не «переигрываются», а
   приложение дёргает endpoint (админский ключ) и получает свежие черновики; офлайн —
   локальная GGUF. Черновики идут в очередь приёмки как сейчас (`trusted=0`).
4. **Ротация типов**: на одной теме типы чередуются принудительно (термин → ошибка в
   утверждении → верно/неверно → причина-следствие). Реализуется фильтром `kind`+
   подтипом в промпте; уже заложено в батч-промпт, в рантайме — выбор по счёчику попыток.
5. **Вариативность формулировок одного факта**: при генерации просим разные углы; в приёмке
   дубли по answer отсеиваются (нормализатор + одинаковый ответ = дубль).
6. **Персональные seed'ы**: два ученика одной темы видят разные наборы и порядки —
   переписывание ответов в классе обесценивается.
7. **Антипаттерны в промпте**: запрет «ряды/последовательности по порядку тем», запрет
   подсказки ответом в формулировке, лимит «не более 1 верно/неверно подряд».
8. **Маскирование порядка**: выдача не следует порядку ФРП буквально — внутри раздела
   темы перемешиваются, новая тема открывается по mastery предыдущих (не по номеру).
